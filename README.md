# backup

Linux 服务器通用备份与恢复脚本。POSIX 兼容，可同时运行于 `sh` 与 `bash`，适配新旧各版本 Linux 发行版。通过 `.env` 文件或环境变量配置，无需改动脚本即可适配不同业务。

## 特性

- **POSIX 兼容**：仅使用标准语法与基础命令，无 bash 专属特性，`sh` / `bash` 通用。
- **配置与逻辑分离**：所有可变参数通过 `.env` / 环境变量注入，脚本本体零修改复用。
- **路径锚定脚本目录**：相对路径的 `SRC_DIR` / `BACKUP_DIR` / `LOG_DIR` 相对脚本所在目录解析，cron / 任意 CWD 下行为一致。
- **并发锁**：`mkdir` 锁防止重复执行（双 cron、手动 + cron），自动清理残留失效锁。
- **前置校验**：必填项、路径、依赖在执行核心逻辑前一次性校验，提前报错终止。
- **故障兜底**：`trap` 捕获所有退出路径；若服务停止曾被执行，退出时强制尝试启动，并释放锁，杜绝业务长期停摆。
- **归档完整性校验**：备份后 `tar -tzf` 校验；`tar` 非 0 退出但校验通过时告警保留，校验失败才删除。
- **滚动清理**：按时间戳保留最新 N 份备份与日志，超出自动删除。
- **安全恢复**：先解压校验 → 旧数据同卷重命名挪开 → 新数据就位 → 成功后再删旧数据；失败自动回滚。可选恢复前快照。
- **极简输出**：仅保留关键节点提示，错误信息统一携带返回码。

## 项目结构

```
.
├── backup.sh        # 核心备份 / 恢复脚本（POSIX）
├── .env.example     # 配置模板（复制为 .env 后修改）
├── .gitignore       # 忽略 .env 与 logs/
└── README.md        # 项目说明
```

运行后会在配置目录下生成备份包与日志：

```
{BACKUP_DIR}/{PREFIX}_backup_{YYYYMMDD_HHMMSS}.tar.gz   # 备份压缩包
{LOG_DIR}/{PREFIX}_backup_{YYYYMMDD_HHMMSS}.log         # 备份运行日志
{LOG_DIR}/{PREFIX}_restore.log                          # 恢复运行日志（每次覆盖）
{LOG_DIR}/.{PREFIX}_run.lock/                           # 运行锁（退出自动删除）
```

## 快速开始

1. 复制配置模板并填写必填项：

   ```sh
   cp .env.example .env
   vi .env
   ```

2. 编辑 `.env`，至少填写 4 个必填变量（服务停止命令、源数据目录、备份目录、服务启动命令）：

   ```sh
   STOP_CMD="systemctl stop myapp"
   START_CMD="systemctl start myapp"
   SRC_DIR="/opt/myapp/data"
   BACKUP_DIR="/var/backups/myapp"
   ```

3. 赋予执行权限并运行备份：

   ```sh
   chmod +x backup.sh
   ./backup.sh
   ```

4. （可选）加入定时任务，每天凌晨 2:30 执行：

   ```sh
   crontab -e
   # 添加：
   30 2 * * * /path/to/backup.sh
   ```

## 使用方式

```
./backup.sh                                  # 执行备份
./backup.sh --restore-latest                 # 恢复最新备份
./backup.sh --restore-latest --target-dir /new/path
                                             # 恢复到指定目录
```

| 选项 | 说明 |
| --- | --- |
| `--restore-latest` | 将 `BACKUP_DIR` 中最新的备份恢复到 `SRC_DIR`（交互式，带完整性预检与失败回滚）。 |
| `--target-dir <目录>` | 覆盖 `SRC_DIR`，对备份和恢复模式均生效（最高优先级；相对路径相对当前工作目录）。 |

## 配置说明

所有变量遵循优先级：**系统环境变量 > `.env` 文件 > 内置默认值**。已存在的系统环境变量不会被 `.env` 覆盖，支持运行时临时覆写。

相对路径（`SRC_DIR`、`BACKUP_DIR`、`LOG_DIR`）在配置中一律相对**脚本所在目录**解析；`--target-dir` 的相对路径相对**当前工作目录**解析（符合命令行直觉）。

| 变量 | 必填 | 默认值 | 说明 |
| --- | :---: | --- | --- |
| `STOP_CMD` | 是（备份） | — | 停止服务的命令；恢复时若已配置也会先停服 |
| `START_CMD` | 是（备份） | — | 启动服务的命令；恢复时若配了 `STOP_CMD` 则必填 |
| `SRC_DIR` | 是 | — | 待备份/恢复的源数据目录（相对脚本目录或绝对路径） |
| `BACKUP_DIR` | 是 | — | 备份压缩包存放目录（不存在自动创建） |
| `MAX_BACKUPS` | 否 | `30` | 备份包与日志共享的最大保留份数（正整数） |
| `BACKUP_PREFIX` | 否 | `app` | 备份包与日志文件名前缀（也是锁文件名的一部分） |
| `LOG_DIR` | 否 | `./logs/` | 日志与运行锁目录（不存在自动创建） |

## 备份工作流程

脚本严格按「校验 → 加锁 → 停服 → 备份 → 校验 → 启服 → 清理」顺序执行，任一步失败走对应兜底分支：

1. **前置校验**：加载配置 → 解析相对路径 → 检查必填项 → 校验 `MAX_BACKUPS` 为正整数 → 校验源目录存在 → 自动创建备份/日志目录 → 生成运行时间戳。
2. **获取锁**：在 `LOG_DIR/.{PREFIX}_run.lock` 上取 `mkdir` 锁；已有存活进程持锁则报错退出，失效锁（进程已死）自动清除后重试。
3. **停止服务**：执行 `STOP_CMD` 并校验返回码。失败则尝试启动服务、释放锁后报错退出，不进入备份。
4. **数据备份**：`tar -zcf` 按源目录 basename 打包（保证归档可移植性）。
5. **完整性校验**：`tar -tzf` 验证归档。`tar` 返回非 0 但校验通过 → 告警并保留；校验失败 → 删除残缺包、启动服务、报错退出，不执行清理。
6. **启动服务**：执行 `START_CMD`。失败仅输出告警，不影响已生成的备份，脚本正常结束。
7. **滚动清理**：仅备份成功后执行，分别对备份包与日志按 `MAX_BACKUPS` 保留最新 N 份。

## 恢复工作流程（`--restore-latest`）

将 `BACKUP_DIR` 中最新的备份恢复到 `SRC_DIR`。交互式流程；若配置了 `STOP_CMD` / `START_CMD`，会在改数据前停服、结束后启服。

1. **校验归档**：定位最新备份（排除 `before_restore`），先 `tar -tzf` 损坏检测——不通过则不锁不停服、直接拒绝。
2. **获取锁**：防止恢复进行中并发备份。
3. **确认恢复**：打印最新备份路径与恢复目标，询问确认。输入 `y` 或 `yes` 继续；其他取消（此时尚未停服）。
4. **选择现有数据处理方式**：
   - `1` — 直接覆盖现有数据目录（仍走「挪开旧数据 → 写入新数据 → 成功后删旧」的可回滚顺序）。
   - `2` — 先将当前数据备份为 `{PREFIX}_backup_before_restore.tar.gz`，再覆盖。安全快照使用固定文件名（每次恢复覆盖），**不计入** `MAX_BACKUPS`。
   - `3` — 取消。
   - 输入非 `1` 非 `2` 的值均视为 `3`（取消）。
5. **停服**（若配置了 `STOP_CMD`；未配置则告警后继续）。
6. **安全换入**：
   - 解压到临时目录并确认非空；
   - 旧 `SRC_DIR` 同文件系统 `mv` 挪到一侧（`{SRC_DIR}.pre_restore.$$`）；
   - 新数据 `mv` 就位（单顶层目录直接替换；多顶层条目全部移入 `SRC_DIR`）；
   - 全部成功后才删除临时目录与挪开的旧数据；
   - 任一步失败：自动把旧数据挪回原位，报错退出（`trap` 负责启服与解锁）。
7. **启服 / 解锁**：由 `EXIT` 统一兜底执行。

恢复默认读取配置中的 `SRC_DIR` 和 `BACKUP_DIR`。如需恢复到其他位置：

```sh
# 通过 CLI 参数（最高优先级；相对路径相对当前工作目录）
./backup.sh --restore-latest --target-dir /opt/myapp/data_restored

# 通过系统环境变量
SRC_DIR=/opt/myapp/data_restored ./backup.sh --restore-latest
```

## 异常与兜底

`trap ... EXIT` 捕获正常退出、报错退出与中断信号（`INT` / `HUP` / `TERM`）。退出时先尝试启服（若 `STOP_CMD` 曾实际执行），再释放运行锁——任何退出路径都不会把服务留在停止状态，也不会留下被本进程持有的锁。恢复模式未停服时，启服步骤为空操作。

分级失败策略（备份模式）：

| 场景 | 行为 |
| --- | --- |
| 已有存活实例持锁 | 不执行任何操作；报错退出 |
| 停服失败 | 不执行备份；尝试启服；释放锁；报错退出 |
| 打包/校验失败 | 删除残缺包；启服；释放锁；报错退出；不执行清理 |
| 启服失败 | 仅输出告警；备份已生效；脚本正常结束 |
| 清理失败 | 不影响主流程；记录告警日志 |

分级失败策略（恢复模式）：

| 场景 | 行为 |
| --- | --- |
| 归档损坏 | 停服前拒绝；不碰现有数据 |
| 停服失败 | 不改数据；尝试启服；解锁；报错退出 |
| 挪开旧数据失败 | 保留旧数据原位；解压临时目录清理；报错退出 |
| 新数据就位失败 | 旧数据自动挪回；报错退出；启服 |

## 滚动清理

- **匹配规则**：备份包匹配 `{PREFIX}_backup_*.tar.gz`，日志匹配 `{PREFIX}_backup_*.log`。文件名含 `before_restore` 的文件被排除，恢复安全快照不会被清理或计入上限。
- **排序规则**：按文件名字典序倒序排列（文件名含时间戳，字典序等同于时间序），不依赖文件 mtime。
- **执行时机**：仅备份成功后执行，避免备份失败时误删历史可用备份。

## 日志

- 每轮运行的日志文件名与备份包一一对应（恢复模式为运行日志），共用同一时间戳。
- 所有输出同时写入终端与日志文件；关键节点（停服、备份完成、启服、清理完成）同步终端提示。
- 错误信息统一携带 `[ERROR]` 标识与返回码。
- 备份日志与备份包共享 `MAX_BACKUPS` 保留上限，清理逻辑完全一致。

## 使用示例

**运行时覆写参数**（不改 `.env`）：

```sh
MAX_BACKUPS=10 BACKUP_PREFIX=db ./backup.sh
```

**查看最新日志**：

```sh
ls -t logs/*.log | head -1 | xargs less
```

**交互式恢复最新备份**：

```sh
./backup.sh --restore-latest
```

## 兼容性

- 语法：仅使用 POSIX 标准（`[ ]` 判断、`.` 加载、无数组 / 关联数组 / bash 字符串截取）。
- 命令：`date +%Y%m%d_%H%M%S`、`tar -zcf`/`-zxf` 搭配 `-C`、`ls` + `sort`、`mkdir` 锁，均使用标准参数。
- 已通过 `sh` 与 `bash` 语法校验，并覆盖：备份成功、配置缺失、停服失败（含尝试启服）、打包/校验失败、滚动清理、环境变量覆写、默认值、参数校验、源目录缺失、根目录恢复拒绝、相对路径跨 CWD、并发锁阻断与失效锁恢复、`STOP_CMD` 无 `START_CMD` 拒绝恢复；恢复全流程（覆盖、先备份再恢复、取消、目标目录、环境变量覆盖、无备份归档、非 1/2 默认取消、损坏归档拒收、多顶层条目归档、空格路径）。

## 常见问题

- **报错 "missing required config"**：`.env` 中有必填变量留空，按提示补齐。
- **报错 "source directory does not exist"**：`SRC_DIR` 路径不存在或不是目录（相对路径以脚本目录为基准）。
- **报错 "MAX_BACKUPS must be a positive integer"**：`MAX_BACKUPS` 必须为 ≥ 1 的整数。
- **报错 "backup directory does not exist"**（恢复）：`BACKUP_DIR` 中需已有备份归档。
- **报错 "another instance is already running"**：已有备份/恢复在执行；等待结束或确认进程已死后重跑（失效锁会被自动清除）。
- **报错 "backup archive is corrupt or unreadable"**：最新归档损坏，恢复已在停服前中止；请换更早的归档或重新备份。
- **报错 "STOP_CMD is set but START_CMD is empty"**：恢复前要停服就必须同时能启服，补齐 `START_CMD`。
- **备份/日志目录不存在**：脚本会自动递归创建，无需手动建立。
- **首次运行**：正常生成备份与日志，无历史时跳过清理。
- **启服告警但备份成功**：检查 `START_CMD` 是否正确；归档已生成且通过 `tar -tzf` 校验。
- **恢复被取消**：重新运行，在确认提示输入 `y`/`yes`，在操作提示输入 `1` 或 `2`。
- **cron 日志位置不对**：确认 `.env` 中路径；相对路径已锚定脚本目录，不应再依赖 cron 的 HOME。
